# 出口自动恢复

Resin 在 CONNECT/SOCKS 隧道失败时直接通知路由模块；Sub2API 等调用方通过已有鉴权接口提交失败反馈。
两条路径共用自动恢复入口，不读取其他项目的数据库或日志，不依赖请求日志开关。

## 运行与配置

系统设置的「出口自动恢复」支持启停、每平台每分钟最多恢复账号数（默认 20，范围 1–100）、
达到上限后的暂停时长（默认 300 秒，范围 60–3600）。修改沿用现有配置保存入口，立即用于后续恢复。
单账号至少间隔 30 秒；15 分钟内恢复 3 次后暂停 1 小时。这些约束只作用于自动恢复，管理员仍可手动轮换。

每次恢复先比较账号、节点和租约创建代次。并发或重复的旧反馈不会修改新租约、消耗恢复次数，
也不会让旧连接中断。没有可用替代节点时保留原租约；受限但有效的失败反馈仍记录目标冷却，
避免冷却结束后重新选择刚失败的出口。关闭自动恢复时不新增冷却记录。
浏览器任务的 guarded 租约、客户端取消、客户端写入失败均不触发自动轮换。

一次 CONNECT 最多拨号三个不同节点。首次拨号失败时核对恢复条件并记录观察到的租约，后续候选只读选择，
成功后重新校验共享限额，对最初观察到的租约做一次 CAS 提交；中途管理员已更换租约时不覆盖新绑定。
三个节点都失败时不把它们重新选作替代。只有成功轮换才消耗一次预算，取消或无替代不会把账号封入长时间冷却。
预算受限时仍允许有界重试，但成功连接仅服务当前请求，不改账号租约，也不登记为该租约的新连接。
恢复尝试对象只归属当前连接，没有全局令牌表或额外清理任务。

系统设置同时展示本次进程启动以来的恢复、限流、无替代次数，当前暂停的平台数量和最近处理结果/时间。
管理接口为 `GET /api/v1/system/recovery`，仅接受管理员鉴权，不返回账号、凭据或节点身份。
计数和限流状态在内存中有界保存（最多 4096 个账号、256 个平台）；重启后重新计数。
此限额约束失败驱动的恢复；正常租约到期续租、拓扑节点移除后的重新路由仍沿用原生路由规则。
容量达到上限时拒绝新的自动恢复，过期状态在下一次恢复时释放，不驱逐仍生效的保护记录。

接口反馈在受限或关闭时返回 `recovery_limited`，保持原租约。调用方不得把它视为成功轮换，
也不得无限重试；此前的 `available`、`rotated`、`stale_lease`、`no_alternative` 契约继续保留。

## 外部日志守卫的退役条件

此变更覆盖 Resin 自己可见的隧道错误及客户端的结构化反馈。Sub2API 生产必须先运行带
`resinrecovery` 的版本并完成真实链路验收，才能停止 `resin-egress-guard.service` 的旧日志读取。
部署 Resin 新版本本身不代表外部守卫已经停用。蓝绿、NAT、共享 Xray 池和主机网络维护仍由服务器模块负责。

相关实现分布在 `internal/routing/rotation_storm_guard.go`、`lease_recovery.go`、代理失败回调、
`internal/service/control_plane_recovery.go` 与原有系统设置页；无新增后台进程、任务队列或数据库表。

## 维护接口与存储边界

订阅详情及列表增加 `managed_node_count`（含淘汰节点）和 `evicted_node_count`。
现有 `node_count` 仍指未淘汰节点；同一次内存遍历保证三者满足
`managed_node_count = node_count + evicted_node_count`。禁用订阅仍保留这些计数，健康数量为零。
维护器通过原有鉴权 API 读取当前服务进程的计数，不再读取可能延迟落盘的 `cache.db`，
也不需要了解蓝绿目录或部署记录。缺少字段或计数不一致时，在修改订阅前明确失败。
